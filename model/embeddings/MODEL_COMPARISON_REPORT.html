Why V3 Contrastive Failed: Embedding Collapse

The contrastive model collapsed to a trivial solution — all 332 subzones mapped to nearly the same point in embedding space (cosine similarity ≈ 1.0 for ALL pairs). Root cause: 33:1 positive-to-negative pair imbalance (53K positive pairs from adjacency/same-area signals vs only 1.6K negative pairs). The model learned to minimize loss by simply mapping everything close together, satisfying all positive constraints while having too few negative constraints to push dissimilar subzones apart.

Evidence: 327 of 332 subzones landed in a single cluster. Orchard's nearest neighbors became Yishun West and Khatib (random residential areas) instead of Somerset and Jurong Gateway.

Fix (not implemented): Hard negative mining, balanced sampling (1:1 ratio), NT-Xent loss with temperature scaling, larger negative batch size.

Winner: V2 Autoencoder+ (363 features)

V2 improves on V1 with 10%% better reconstruction (0.198 vs 0.220) while maintaining strong separation (0.779). The 44 new features from ACRA business registry, HDB resale prices, private property, co-location graphs, and demographic trends add real signal. V1 remains a solid baseline. V3 contrastive approach needs architectural fixes before it can be useful.
